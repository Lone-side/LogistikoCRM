# Obligation Engine — Κανόνες

1. **Καμία hardcoded προθεσμία σε views/tasks.** Οι προθεσμίες προκύπτουν
   από τη ρύθμιση του `ObligationType` (πεδία κανόνα προθεσμίας) και τις
   ρυθμίσεις ανά πελάτη (`ClientObligation`). Αν χρειάζεται νέος κανόνας,
   επεκτείνεται το μοντέλο — όχι if/else σε view.
2. **Versioning / ιστορικό**: αλλαγή κανόνα προθεσμίας δεν αλλοιώνει
   υπάρχουσες υποχρεώσεις. Κάθε παραγόμενη `MonthlyObligation` κρατά την
   προθεσμία που υπολογίστηκε κατά τη δημιουργία της (snapshot), όχι
   δυναμικό υπολογισμό.
3. **Αργίες/εργάσιμες/παρατάσεις**: υπολογισμοί «τελευταία εργάσιμη» και
   επίσημες παρατάσεις μοντελοποιούνται ως δεδομένα (πίνακες/ρυθμίσεις),
   όχι ως σταθερές στον κώδικα. Παράταση = νέα εγγραφή με πηγή (βλ. skill
   greek-tax-domain), όχι mutation της αρχικής προθεσμίας σιωπηλά.
4. **Καταστάσεις**: pending / in_progress / completed / overdue / cancelled.
   Διαγραφή ιστορικού απαγορεύεται για μη-admins — ακύρωση αντί διαγραφής.
5. **Μαζικές πράξεις**: bulk complete/notify περνούν ΠΑΝΤΑ από τα ίδια
   permission checks με τις μεμονωμένες (RBAC: `ClientScopedQuerysetMixin`).
6. **Tests**: κάθε αλλαγή στον υπολογισμό προθεσμιών θέλει test με
   πραγματικές ελληνικές περιπτώσεις (μήνας με αργία, τριμηνιαίο ΦΠΑ,
   αλλαγή έτους/rollover).
