## 3. Pre-deploy backup — P0

Στον office server, πριν σταματήσει οποιοδήποτε service:

```bash
cd /opt/logistikocrm
COMPOSE="docker compose -f docker-compose.prod.yml -f docker-compose.office.yml"
$COMPOSE exec -T web python manage.py backup_database
$COMPOSE exec -T web python manage.py restore_database --list
```

- [ ] Υπάρχει νέο `crm_db_<timestamp>.pgdump`.
- [ ] Υπάρχει αντίστοιχο `crm_media_<timestamp>.tar.gz`.
- [ ] Τα δύο αρχεία εξήχθησαν από το named volume.
- [ ] Υπολογίστηκαν SHA-256 checksums.
- [ ] Αντιγράφηκαν σε **δεύτερο φυσικό μέσο/host**, όχι άλλο path του ίδιου disk.
- [ ] Το off-host αντίγραφο είναι κρυπτογραφημένο με κλειδί διαφορετικό από
      τον server και το κλειδί έχει ελεγχθεί ότι είναι διαθέσιμο.

```bash
mkdir -p ../logistikocrm-backup
$COMPOSE cp web:/app/backups/. ../logistikocrm-backup/
sha256sum ../logistikocrm-backup/crm_db_* ../logistikocrm-backup/crm_media_* \
  > ../logistikocrm-backup/SHA256SUMS
sha256sum -c ../logistikocrm-backup/SHA256SUMS
```

> Αποδεκτές δωρεάν διαδρομές: κρυπτογραφημένο αφαιρούμενο μέσο που
> αποσυνδέεται μετά την αντιγραφή ή δεύτερος ελεγχόμενος host μέσω Tailscale.
> Απλή αντιγραφή σε άλλο φάκελο του ίδιου server **δεν** είναι off-host backup.

## 5. Controlled deployment — P0

Οι writers παγώνουν πριν από migrations. Δεν χρησιμοποιείται το legacy
`git pull && up -d --build` ως ανεξέλεγκτο mixed-version rollout.

```bash
cd /opt/logistikocrm
COMPOSE="docker compose -f docker-compose.prod.yml -f docker-compose.office.yml"
OLD_SHA=$(git rev-parse HEAD)
printf '%s\n' "$OLD_SHA" > ../logistikocrm-rollback-sha.txt

git fetch origin
git checkout --detach <APPROVED_RELEASE_SHA>
$COMPOSE build web celery celery-beat nginx

# Πάγωμα όλων των writers και του reverse proxy.
$COMPOSE stop nginx web celery celery-beat

# Migration με one-off container ενώ η PostgreSQL παραμένει διαθέσιμη.
$COMPOSE run --rm web python manage.py migrate --noinput
$COMPOSE run --rm web python manage.py audit_voipcalllog_snapshots --fail-on-findings
$COMPOSE run --rm web python manage.py audit_clientdocument_invariants

# Ίδιο image για web/workers/beat.
$COMPOSE up -d web celery celery-beat nginx
./scripts/office_preflight.sh
```

- [ ] Δεν έτρεξαν old/new workers ταυτόχρονα.
- [ ] Το migration exit code ήταν 0.
- [ ] Δεν υπήρξε απρόσμενη κατηγορία document-invariant finding.
- [ ] Το VoIP snapshot audit ήταν καθαρό.
- [ ] Όλα τα containers είναι healthy.
- [ ] Το preflight γράφει `Αποτέλεσμα: όλα πράσινα.`

## 9. Rollback — P0

### Χωρίς destructive migration/data write

```bash
$COMPOSE stop nginx web celery celery-beat
git checkout --detach "$(cat ../logistikocrm-rollback-sha.txt)"
$COMPOSE build web celery celery-beat nginx
$COMPOSE up -d web celery celery-beat nginx
./scripts/office_preflight.sh
```

### Με migration ή πιθανή αλλαγή δεδομένων

**Δεν** κάνουμε τυφλό reverse migration. Εκτελείται maintenance restore από το
verified pre-deploy backup, ακολουθώντας το `DEPLOYMENT.md §Backups`, με όλους
τους writers σταματημένους. Μετά το restore τρέχει preflight και smoke suite.

Άμεσο rollback αν συμβεί οποιοδήποτε από τα παρακάτω:

- migration/audit exit ≠ 0,
- health/readiness κόκκινο για πάνω από 5 λεπτά,
- επαναλαμβανόμενο 500 σε login/client/document endpoints,
- απώλεια πρόσβασης σε media ή mismatch database/media,
- μη εξουσιοδοτημένη ή ανεξήγητη door action,
- duplicate πραγματικό email ή myDATA submission,
- ασυνήθιστη αύξηση errors/container restarts.
